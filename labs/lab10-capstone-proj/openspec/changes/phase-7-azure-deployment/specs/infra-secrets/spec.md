## ADDED Requirements

### Requirement: Key Vault provisioning
The system SHALL provision an Azure Key Vault `kv-skillplatform-prod` in `japaneast` with SKU `standard`, soft-delete enabled (90-day retention), purge protection enabled, public network access disabled, and `enable_rbac_authorization = true` (RBAC mode, not legacy access policies). A Private Endpoint in `snet-pe` SHALL be the only network path to the vault.

#### Scenario: Key Vault uses RBAC, not access policies
- **WHEN** an operator inspects the Key Vault's Access Configuration blade
- **THEN** the permission model is `Azure role-based access control`

#### Scenario: Public access disabled
- **WHEN** an operator inspects the Key Vault's Networking blade
- **THEN** "Allow public access from specific virtual networks and IP addresses" is OFF and the Private Endpoint is the only connection method

### Requirement: Required secrets populated
The system SHALL populate the following secrets in Key Vault as part of the Terraform apply:
- `database-url` — full Postgres URL with URL-encoded password.
- `storage-connection-string` — Storage Account connection string from Terraform output.
- `cosmos-connection-string` — Cosmos DB primary connection string.
- `google-client-id`, `google-client-secret` — values provided via Terraform variables.
- `jwt-private-key` — RS256 private key (PEM, multi-line) provided via a Terraform variable.
- `jwt-public-key` — corresponding public key.
- `appinsights-connection-string` — Application Insights connection string from Terraform output.
- `scanner-shared-secret` — random 64-char string generated by `random_password` and reused between the scanner Function and the NestJS internal endpoint.

#### Scenario: All secrets exist post-apply
- **WHEN** an operator runs `az keyvault secret list --vault-name kv-skillplatform-prod`
- **THEN** the listed secret names are exactly the nine above (any additional secrets must be a no-op for Phase 7)

#### Scenario: jwt-private-key round-trips multi-line content
- **WHEN** an operator runs `az keyvault secret show --vault-name kv-skillplatform-prod --name jwt-private-key`
- **THEN** the returned `value` field is a PEM-formatted private key with literal newlines (not `\n` escapes)

### Requirement: Managed identity RBAC grants
The system SHALL assign the following Azure RBAC roles to the system-assigned managed identities of the compute resources:
- App Service MI: `Key Vault Secrets User` on the Key Vault; `Storage Blob Data Contributor` on the Storage Account; `Cosmos DB Built-in Data Contributor` on the Cosmos account.
- Function App MI: `Key Vault Secrets User` on the Key Vault; `Storage Blob Data Contributor` on the Storage Account; `Cosmos DB Built-in Data Contributor` on the Cosmos account.
- Container App MI: `AcrPull` on the ACR; `Monitoring Metrics Publisher` on the App Insights resource.

#### Scenario: App Service MI can read a Key Vault reference
- **WHEN** the App Service is configured with an app setting `DATABASE_URL = "@Microsoft.KeyVault(SecretUri=https://kv-skillplatform-prod.vault.azure.net/secrets/database-url/)"` and the App Service is restarted
- **THEN** `process.env.DATABASE_URL` inside the running app holds the secret's plaintext value

#### Scenario: Container App MI can pull from ACR
- **WHEN** the Container App is configured to pull `acrskillplatformprod.azurecr.io/thumbnail:<tag>` using its system-assigned identity
- **THEN** the revision starts successfully without requiring an admin user or registry credential
