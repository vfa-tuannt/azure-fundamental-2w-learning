## Why

Phases 0–6 produced a feature-complete platform that runs entirely on a developer laptop (Docker Compose Postgres, Azurite blob emulator, Postgres-backed activity log). The original goal of the project — and the underlying 2-week Azure learning plan — is to land the same product on Azure so every service from the learning plan is exercised with a clear architectural purpose: App Service (web hosting), Azure Functions (serverless), Container Apps (containerized workloads), Azure Database for PostgreSQL (managed RDBMS), Blob Storage + Key Vault (storage + secrets), API Management (gateway), Application Insights (observability), GitHub Actions (CI/CD), and **Virtual Network (VNet isolation — Day 8 of the learning plan, missing from the original PRD)**. Phase 7 also doubles as a hands-on Azure portal tour: the implementer is new to Azure and needs each task to be small enough to verify visually in the portal before moving on.

## What Changes

- **NEW Terraform-as-code layer.** A fresh `infra/` directory holds the root module plus per-resource modules: `resource_group`, `network` (Day 8 VNet/subnets/NSG/Private Endpoints/Private DNS — additive vs the PRD), `postgres`, `storage`, `key_vault`, `app_insights` (+ Log Analytics workspace), `cosmos`, `acr`, `app_service`, `static_web_app`, `functions`, `container_apps`, `apim`. Remote state lives in a dedicated Storage Account container provisioned out-of-band (a tiny `bootstrap/` script handles this once). Resource Group + naming/tagging convention (`skillplatform-<env>-<purpose>`) is enforced via locals.
- **NEW VNet layer (Day 8 add).** A `10.20.0.0/16` Virtual Network with four subnets: `snet-app` (delegated to App Service for VNet integration), `snet-pe` (Private Endpoints), `snet-db` (delegated to Postgres Flexible Server), `snet-aca` (Container Apps environment). NSGs default-deny inbound from the internet on `snet-pe`/`snet-db`. Private Endpoints + Private DNS zones for Postgres, Storage (`blob`), Key Vault, Cosmos DB, and ACR. App Service uses VNet integration to reach all backend resources privately; only APIM is publicly exposed (and APIM itself is locked to its consumption-tier public endpoint with rate limiting and JWT validation).
- **NEW backend deployment to Azure App Service.** App Service Plan B1 Linux + App Service for NestJS (Node 24). System-assigned Managed Identity reads `@Microsoft.KeyVault(SecretUri=...)` references for `DATABASE_URL`, `AZURE_STORAGE_CONNECTION_STRING`, `COSMOS_CONNECTION_STRING`, Google OAuth client secret, and the JWT RS256 private key. Production `CORS_ORIGIN` is the Static Web App URL. `applicationinsights` SDK is wired at startup using the connection string env var.
- **NEW frontend deployment to Azure Static Web Apps (Free).** Build with `yarn build`, deploy via GitHub Actions Static Web Apps action. `VITE_API_URL` points at the APIM public URL once APIM is wired (later sub-phase). SPA fallback configured via `staticwebapp.config.json`.
- **NEW Azure Functions (Python v2 model, Consumption plan).** Two functions in a new top-level `functions/` directory:
  - `submission_scanner`: `@app.blob_trigger` on the `submissions` container — validates MIME type + size, writes a result to Cosmos `submission_events`, calls back into NestJS `POST /internal/submissions/:id/invalidate` (new internal-only endpoint guarded by a shared secret from Key Vault) if invalid.
  - `weekly_report`: `@app.timer_trigger` schedule `0 0 2 * * 1` (Mon 09:00 UTC+7 == 02:00 UTC) — queries Postgres for open challenges with `< 50%` enrollment, writes `reports/weekly-{YYYY-MM-DD}.json` to Blob Storage.
- **NEW Container App — thumbnail preview microservice (Node 24).** New top-level `services/thumbnail/` directory: `POST /thumbnail` accepts `{ blobUrl }`, returns a 256×256 PNG. Uses `sharp` for images, `pdf-thumbnail` for PDFs, a placeholder SVG for other types. Image is built and pushed to ACR; deployed to Azure Container Apps with min 0 / max 3 replicas (scale-to-zero). NestJS gains a small client that, after a successful file submission, calls the service and stores the returned URL on `submissions.thumbnail_url` (new column; migration included). FE submissions list renders the thumbnail when present.
- **NEW Cosmos DB persistence for activity events.** A new `CosmosActivityRepository` implements the existing `ActivityRepository` port introduced in Phase 6, swapping reads/writes to Cosmos `activity_events` (partition key `/userId`). The Postgres `activity_events` table is dropped via a TypeORM migration. `GET /activity/recent` and `GET /activity/me` keep the exact same response shape; the FE is not modified.
- **NEW API Management gateway (Consumption tier).** All public traffic enters via APIM. The NestJS App Service is registered as the `skillplatform-api` backend (proxied at `/api/*`); the thumbnail Container App is the `skillplatform-thumbnail` backend (proxied at `/thumbnail/*`). Policies: per-IP rate limit 100 calls/min, CORS for the Static Web App origin, `validate-jwt` (RS256 with our public key) for non-public routes — the `/auth/*` routes and `GET /activity/recent` stay anonymous. The NestJS Swagger document is exported and imported into APIM as the API definition, which auto-populates the Developer Portal.
- **NEW observability layer.** Application Insights is the single sink for App Service, Container Apps, and Functions (all three share one App Insights connection string from Key Vault). NestJS emits custom telemetry events (`challenge.created`, `enrollment.created`, `submission.uploaded`, `submission.approved`, `submission.rejected`) via the existing service hooks added in Phase 6. A Portal dashboard is provisioned via Terraform showing request rate, failure rate, average latency, and a custom-events timeline. Alert rule: notify (email action group) when 5xx rate `> 5%` over a 5-minute window.
- **NEW CI/CD via GitHub Actions.** Four workflows under `.github/workflows/`: `backend.yml` (lint → typecheck → test → build → deploy App Service), `frontend.yml` (typecheck → build → deploy Static Web App), `functions.yml` (lint → deploy Function App via `azure/functions-action`), `container-app.yml` (build Docker → push ACR → update Container App revision). Authentication is OIDC-based federated credentials (no long-lived secrets in GitHub); only the federated app's client ID + tenant ID + subscription ID live in GitHub secrets.
- **NEW newbie-friendly task structure.** `tasks.md` is intentionally broken into small portal-visible checkpoints (e.g., "create resource group via Portal, screenshot the overview blade, then re-create via Terraform"). Each task ends with a verification step the user can perform in the Azure Portal so a first-time Azure user can build confidence incrementally.
- **MODIFIED backend-submissions capability.** `submissions.thumbnail_url` (nullable text) added; the file-submission flow asynchronously enriches the row once the thumbnail service responds. The synchronous response keeps the same shape (thumbnail URL appears on subsequent reads).
- **MODIFIED frontend-submissions capability.** Submission list and detail cards render `thumbnailUrl` when present; gracefully fall back to a file-type icon when absent.
- **MODIFIED backend-activity capability.** The `ActivityRepository` port gets a Cosmos implementation; the contract (response shape, ordering, 50-row cap, public/auth split) does not change.
- **No breaking API changes** to any endpoint already shipped in Phases 1–6. The only public-surface change is that the base URL moves from `https://<app>.azurewebsites.net` to `https://<apim>.azure-api.net` — handled by updating `VITE_API_URL` in the Static Web App build.

## Capabilities

### New Capabilities
- `infra-foundation`: Resource Group, naming/tagging conventions, Terraform layout (root + modules), remote state Storage Account, subscription-level RBAC for the deployment service principal.
- `infra-network`: Day 8 VNet — `10.20.0.0/16`, four subnets, NSG rules, Private Endpoints + Private DNS zones for Postgres / Storage / Key Vault / Cosmos / ACR, App Service VNet integration, Container Apps environment VNet attachment.
- `infra-data`: Azure Database for PostgreSQL Flexible Server (Burstable B1ms, VNet-integrated, no public access), Storage Account (LRS, containers `submissions` + `reports`), Cosmos DB Serverless account + `activity_events` (PK `/userId`) and `submission_events` (PK `/submissionId`) containers.
- `infra-secrets`: Key Vault (Standard, RBAC-mode), required secrets populated (DB conn string, Storage conn string, Cosmos conn string, Google OAuth client ID + secret, JWT private key, App Insights connection string, scanner shared secret), Managed Identity grants for App Service / Function App / Container App.
- `infra-observability`: Log Analytics workspace, Application Insights instance, dashboard, 5xx alert + email action group.
- `infra-acr`: Azure Container Registry (Basic), Managed Identity pull access for Container Apps.
- `infra-app-service`: App Service Plan + App Service for NestJS, system-assigned identity, Key Vault references for all secrets, VNet integration to `snet-app`, deployment slot strategy (production only for v1).
- `infra-static-web-app`: Azure Static Web Apps resource (Free tier) + `staticwebapp.config.json` for SPA routing.
- `infra-functions`: Function App (Linux Consumption, Python 3.11) attached to Application Insights, Managed Identity granted on Storage + Cosmos + Key Vault, App Settings sourced from Key Vault references.
- `infra-container-apps`: Container Apps environment (VNet-attached), thumbnail Container App with scale rules and managed identity.
- `infra-apim`: API Management Consumption-tier instance, two backends, imported OpenAPI from NestJS Swagger, rate-limit / CORS / validate-jwt policies, Developer Portal published.
- `infra-cicd`: Four GitHub Actions workflows + federated OIDC identity, GitHub environments and required reviewers for prod, repo-level secret list documented.
- `backend-functions`: Behaviour of `submission_scanner` (validation rules, Cosmos write shape, NestJS invalidate webhook contract) and `weekly_report` (query, JSON shape, output path).
- `backend-thumbnail-service`: HTTP contract of the thumbnail microservice (`POST /thumbnail`, request/response, supported types, error semantics) plus integration with NestJS post-submission.
- `frontend-thumbnails`: How the FE renders `thumbnailUrl` in the submission list and falls back when absent.

### Modified Capabilities
- `backend-activity`: Persistence is moved from Postgres to Cosmos DB; response contracts unchanged; the `ActivityRepository` port gains a Cosmos implementation; Postgres `activity_events` table dropped via migration.
- `backend-submissions`: New nullable `thumbnail_url` column on `submissions`; post-submission flow calls thumbnail service asynchronously and persists the URL when it arrives; response DTO exposes `thumbnailUrl`.
- `frontend-submissions`: Submission list and detail view consume `thumbnailUrl` when present.

## Impact

- **New top-level directories:** `infra/` (Terraform), `functions/` (Python Azure Functions), `services/thumbnail/` (Node 24 microservice), `.github/workflows/` (4 new workflows).
- **Backend code:** `submissions.thumbnail_url` migration + DTO; `ThumbnailClient` service; `CosmosActivityRepository` + DI swap; drop `activity_events` table migration; `POST /internal/submissions/:id/invalidate` controller (shared-secret guard); `applicationinsights` SDK wiring in `main.ts`.
- **Backend tests:** new unit tests for `ThumbnailClient` (with `nock`), `CosmosActivityRepository` (using `@azure/cosmos` test helpers or a fake), and the new internal invalidate endpoint; existing E2E suite continues to run against local Postgres + Azurite + an in-memory Cosmos shim or skipped when Azure creds unavailable.
- **Frontend code:** thumbnail rendering in `SubmissionList.vue` + detail view; no API changes beyond consuming the new field; `VITE_API_URL` swap at build time.
- **New dependencies:**
  - BE: `@azure/cosmos`, `@azure/identity` (for Managed Identity to KV at runtime if not using app settings references — likely not needed since KV refs are used), `applicationinsights`.
  - Thumbnail service: `express`, `sharp`, `pdf-thumbnail`.
  - Functions: `azure-functions`, `azure-storage-blob`, `azure-cosmos`, `psycopg[binary]`, `requests`.
- **Azure cost target:** stays under PRD's $40/month using the tier choices baked into Terraform (Postgres B1ms, Cosmos Serverless, Container Apps scale-to-zero, APIM Consumption, Static Web Apps Free, ACR Basic, Functions Consumption).
- **Migration path:** activity events are intentionally a fresh start in Cosmos (no historical Postgres → Cosmos copy is required because local-only data is throwaway). The Postgres drop migration is the explicit cutover step.
- **Risk:** APIM Consumption tier has a cold-start; mitigated by APIM's edge caching of the `/api/health` route. Container Apps scale-to-zero means the first thumbnail request after idle is slow; acceptable for v1.
- **Out of scope (still):** custom domain + cert (use the default `*.azurewebsites.net` / `*.azurestaticapps.net` / `*.azure-api.net` hosts), production hardening like WAF, multi-region, blue/green slots. Email notifications still out. Mobile app still out.
