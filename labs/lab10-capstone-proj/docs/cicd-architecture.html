CI/CD — keyless deploy qua GitHub OIDC

Mỗi commit vào main sửa thư mục nào sẽ kích đúng 1 workflow tương ứng deploy lên Azure. Không có long-lived secret nào trong GitHub — chỉ 3 ID. Token Azure được cấp tạm thời qua OIDC trust với Entra ID.

Tại sao OIDC, không phải client secret?

Cách cũ: tạo Service Principal trong Azure, lấy ra một client_secret dài hạn, lưu vào GitHub Secrets. Mỗi lần workflow chạy, dùng secret đó login. Vấn đề: secret nằm trong GitHub vĩnh viễn, có thể leak qua log, qua fork, qua admin cũ — và muốn rotate phải làm thủ công định kỳ.

Cách mới (OIDC federated identity):

  1. Tạo 1 App Registration gh-skillplatform-deploy trong Entra ID.
  2. Thêm Federated credential: "tin tưởng OIDC token có iss=https://token.actions.githubusercontent.com và sub=repo:<org>/<repo>:ref:refs/heads/main".
  3. Gán Contributor role cho App đó chỉ ở scope rg-skillplatform-prod.
  4. Trong GitHub repo, chỉ lưu 3 ID (không phải secret thực sự): AZURE_CLIENT_ID, AZURE_TENANT_ID, AZURE_SUBSCRIPTION_ID.
  5. Khi workflow chạy, azure/login@v2 xin GitHub một OIDC token (signed JWT), gửi lên Entra. Entra verify token đúng repo + đúng branch + đúng app → cấp lại một Azure access token có hiệu lực ~1 giờ.

Kết quả: không secret dài hạn nào tồn tại ngoài Azure. Leak ID → vô dụng nếu không có quyền chạy workflow trên đúng repo. Đổi hệ thống auth = update federated credential, không phải đi vá hàng loạt vault.

An toàn theo nhiều lớp

Scope quyền

  • Contributor chỉ trên rg-skillplatform-prod — không phải toàn subscription.
  • Không động được vào rg-skillplatform-tfstate nếu CI/CD bị compromise.
  • Federated credential ràng buộc ref:refs/heads/main → push lên branch khác không xài được.

Permission YAML phải đúng

  • permissions: { id-token: write, contents: read } — bắt buộc, nếu thiếu id-token: write thì GitHub không cấp OIDC token.
  • Path filter giảm "wasted runs" — chỉ workflow liên quan mới fire.
  • concurrency group để tránh 2 deploy chạy chồng nhau cùng app.

Sequence chi tiết của một push

  1. Dev: git push origin main với commit sửa backend/src/....
  2. GitHub nhận push, scan path filter → kích backend.yml (chỉ workflow này, không workflow khác).
  3. Runner spin up, chạy: yarn lint · tsc · test · build. Fail bất kỳ bước nào → workflow đỏ, không deploy.
  4. Pass → step azure/login@v2 xin OIDC token từ GitHub, gửi lên Entra, nhận Azure access token (~1h).
  5. Step azure/webapps-deploy@v3 dùng token đó push artifact lên App Service app-skillplatform-prod.
  6. Health check GET /api/health sau ≤5 phút phải trả 200 → workflow xanh.
