Overview architecture — high level

Một user, hai cửa vào Azure (SWA cho UI, APIM cho API). Backend NestJS là hub trung tâm gọi đến 3 data store và 2 worker. Diagram này lược bỏ chi tiết VNet/Private Endpoint — đã được mô tả ở network-architecture.html.

Hai cửa vào, một backend

User truy cập platform qua 2 đường. Đây là pattern điển hình của static SPA + API backend trên Azure:

  • Tải UI: browser → Static Web App (free, CDN-cached) tải bundle Vue + asset tĩnh.
  • Gọi API: SPA chạy trong browser → APIM (edge gate) → App Service (NestJS). APIM xử lý CORS, rate-limit, validate JWT trước khi proxy về backend.

App Service không nhận traffic trực tiếp từ Internet — chỉ APIM mới gọi tới được (chặn bằng Access Restriction ApiManagement service tag).

Backend là hub — gọi đến 5 dịch vụ phụ trợ

Data tier (3 store)

  • PostgreSQL Flexible — relational: users, challenges, enrollments, submissions.
  • Cosmos DB Serverless — NoSQL: activity_events, submission_events.
  • Storage Account — blob: file submissions của user + report JSON hàng tuần.

Worker (2 compute)

  • Container Apps — service thumbnail (Express). Scale-to-zero. NestJS gọi sync HTTP để generate ảnh thumbnail từ file submission.
  • Function App — submission_scanner (blob trigger validate file) và weekly_report (cron Mon 02:00 UTC).

Cross-cutting

  • Key Vault — chứa Google secret, JWT private key, connection string. App Service đọc qua @Microsoft.KeyVault reference.
  • ACR — registry chứa image thumbnail:latest + :<sha>.
  • Application Insights — 3 compute share 1 instance, distinguish bằng cloud_role_name.

Hai luồng async đáng chú ý

Hai mũi tên đứt nét trong sơ đồ thể hiện 2 luồng không-đồng-bộ rất "Azure":

  1. Storage → Function (blob trigger): user upload file → Storage event tự động kick Function App. Function validate MIME + size; nếu invalid, ghi Cosmos submission_events và POST về NestJS /internal/submissions/:id/invalidate (mũi tên dashed trở lại App Service).
  2. App Service → Container Apps (thumbnail): NestJS trả response cho user ngay sau khi commit DB row, dispatch thumbnail request ở background. Khi ACA trả về URL ảnh, NestJS UPDATE thumbnail_url. User thấy thumbnail ở lần xem kế tiếp.

Pattern này tránh ép user chờ cold-start của Container Apps (5–10s) hoặc trễ của blob scan.
